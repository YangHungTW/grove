# Architecture — per-agent default skills

Generated: 2026-07-29T11:12:33Z

## Decision 1 — `src/core/skills.ts` stays browser-safe; fs is injected

The renderer needs `withSkills()` (to compose the prompt) and the main process
needs `discoverSkills()` (to enumerate `SKILL.md` files). Putting `node:fs` at
the top of `skills.ts` would drag a Node builtin into the renderer bundle,
which the repo deliberately avoids — the existing split is `settings.ts`
(browser-safe types) vs `settingsStore.ts` (fs-backed).

Splitting into two files would be the obvious answer, but the plan's Files
Touched allows only `src/core/skills.ts`, and Acceptance Criterion 1 requires
the discovery test to run from `src/core/skills.test.ts`.

**Resolution: dependency injection**, following the existing precedent of
`buildAgentLaunch(baseCommand, newId, …)` (`src/core/resume.ts:23`), which
injects `crypto.randomUUID` rather than importing a platform source.

```ts
export interface SkillFs {
  readdir(dir: string): string[]  // entry names; [] when the dir is absent
  readFile(path: string): string  // contents; '' when unreadable
}
export function discoverSkills(fs: SkillFs, opts: {...}): SkillDef[]
```

`skills.ts` therefore imports nothing. Main supplies a ~6-line `node:fs`
adapter; the test supplies the same adapter over a real tmpdir, so the
criterion's "seed real SKILL.md files" requirement is met without the core
module knowing what a filesystem is.

Trade-off accepted: the adapter itself is not unit-tested. It is thin, and
`src/main/index.ts` has no unit tests anywhere in this repo — e2e covers it.

## Decision 2 — composition happens in `startTask`, not `addSession`

`addSession` already takes 7 positional parameters (`store.ts:880-885`).
Threading skills through it would make an eighth, and every non-New-Task caller
would have to pass `undefined`.

Instead `startTask` composes the final prompt and hands the result to the
existing `initialPrompt` parameter:

```ts
const finalPrompt = withSkills(prompt, skillIds, agent.command)
await this.addSession(wt.id, 'agent', agent, undefined, undefined, undefined, finalPrompt)
```

Consequences:
- `addSession`'s signature is untouched; no other call site changes.
- The skill lines flow through the same `shellQuote` positional-argument path
  as the task text, inheriting the `$SHELL -ilc` and tmux re-quoting
  guarantees already documented on `withInitialPrompt`.
- An empty selection returns the prompt string **unchanged**, so the assembled
  command is byte-identical to today's — the plan's central requirement.

## Decision 3 — invocation token is per-CLI, defaulting to `/`

`skillToken(command)` returns `$` for `codex` and `/` for everything else,
mirroring the shape of `supportsResume()` (`resume.ts:9`). Only these two are
verified; Antigravity is unverified, so it takes the `/` default rather than a
guess. Keyed off the command's first word because agents are user-editable and
`id` cannot be trusted.

## Decision 4 — discovery by globbing, not by probing the CLI

`~/.claude/skills/<name>/SKILL.md` and `<repoRoot>/.claude/skills/<name>/SKILL.md`.
The **directory name is the invocable id** (not frontmatter `name`).
Personal wins over project on an id clash, per the docs' precedence rule.
Results sorted by id for a stable list.

Rejected: parsing the stream-json `init` message's `skills` array. It is more
complete (it sees plugin and bundled skills) but costs a model turn and a
subprocess spawn every time the dialog opens.

Known gap, already in Out of Scope: plugin-namespaced skills
(`/yang-toolkit:dashboard`) are not under those paths and will not be listed.
The per-agent defaults field is free text, so they stay reachable by typing.

## Decision 5 — UI shapes

**New Task dialog** — a `.dialog-check` checkbox group placed *after* the agent
radios. Deliberately not a `.dialog-field input`: `e2e/smoke.mjs:345` takes the
first such input as the Branch field. Hidden entirely when nothing is
discoverable and no defaults exist, mirroring the agent radios' "hide when ≤1"
behaviour. Selecting a different agent re-seeds the checkboxes from that
agent's defaults. Any default id that was not discovered is still listed (and
checked) so it is visible rather than silently dropped.

**Settings** — a full-width comma-separated field on each `.agent-edit` row
(the row gains `flex-wrap`). Comma-separated raw text is held in local
component state and committed on blur; deriving the input's value from the
parsed array would delete the comma the moment the user types it.

## Files and order of work

1. `src/core/skills.ts` + `src/core/skills.test.ts` — pure core, tests first.
2. `src/core/settings.ts` — `AgentDef.skills?: string[]` (optional; absent
   loads as `undefined`, so `settingsStore.ts` needs no migration).
3. `src/main/ipc.ts` → `src/preload/index.ts` → `src/main/index.ts` — the
   `skills:available` channel in lock-step, mirroring `agents:available`.
4. `src/renderer/store.ts` — skill cache + `startTask` composition.
5. `src/renderer/Dialog.tsx`, `SettingsPanel.tsx`, `styles.css` — UI.
6. `src/core/settingsStore.test.ts`, `src/renderer/store.test.ts` — round-trip
   and wiring tests.
