# Review — per-agent default skills

Generated: 2026-07-29T11:21:15Z

## Defects found and fixed during review

1. **Wrong invocation token in the dialog label.** The checkbox rows rendered a
   hard-coded `/{id}` even when the selected agent was Codex, whose token is
   `$`. The *composed command* was always correct (it goes through
   `skillToken`), so this was a display-only lie — the worst kind, because the
   user would have had no reason to doubt it. Now derived from
   `skillToken(agent?.command)`, so the label and the launch agree by
   construction.

2. **Fabricated `source` on not-found skills.** Rows synthesized for a
   configured-but-missing skill claimed `source: 'personal'`, which was simply
   untrue. Replaced the row type with `{id, hint}` so nothing is invented.

## Defect found in pre-existing code

`settingsStore.ts:23-24` — documented in `03-implementation`. Fixed minimally;
the broader clobbering bug it belongs to is left untouched and reported.

## Deliberate behaviours worth challenging

- **Switching agent discards a manual skill selection**, re-seeding from the
  new agent's defaults. Correct given the feature is "per-agent defaults", but
  it will surprise anyone who ticks skills first and changes agent second.
- **Skills are only offered in New Task.** A plain agent launch has no initial
  prompt to prepend to, so per-agent defaults do not apply there. Explicitly in
  Out of Scope, but it does mean "per-agent default" is narrower than the name
  suggests.
- **The picker lists local skills only.** Plugin-namespaced skills
  (`/yang-toolkit:dashboard`) are not under `~/.claude/skills` and cannot be
  globbed. They remain usable by typing them into the settings field, and a
  configured-but-not-found skill now gets a labelled row rather than vanishing.

## Residual risk

The end-to-end claim — that a real agent actually loads a skill from a
`/name` first line — is **not covered by this repo's tests** and cannot be:
`CCM_AGENT_CMD` replaces the agent binary in e2e. It rests on the v2.1.220
experiments in `01-discovery`. If a future CLI changes how first-line slash
commands are handled, every test here would still pass while the feature
silently stopped working.
