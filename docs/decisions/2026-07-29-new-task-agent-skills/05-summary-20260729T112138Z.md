# Summary — per-agent default skills in New Task

Generated: 2026-07-29T11:21:38Z

Each agent can now carry a set of default Agent Skills. They arrive pre-checked
in the New Task dialog, can be overridden per task, and — when nothing is
selected — inject absolutely nothing, leaving the launch command byte-identical
to what Grove built before this feature existed.

## The finding that shaped the design

There is **no launch-time skill flag on any agent CLI**. Verified against
Claude Code v2.1.220: `--skill` and `--skills` are both `unknown option`, there
is no `claude skills` subcommand, and the `--agents` JSON `skills:` field
preloads only into a *subagent* — it silently no-ops for the main session
agent. The documented mechanism that does work is invoking the skill from the
first prompt.

So this is prompt composition: N `/skill-name` lines, then the user's task, all
inside the single shell-quoted positional argument Grove already passed.

## Shape

- `src/core/skills.ts` — imports nothing, so the renderer can use `withSkills`
  while `discoverSkills` takes an injected `SkillFs` (the same
  dependency-injection trick as `buildAgentLaunch`'s `newId`).
- Composition happens in `store.startTask`, leaving `addSession`'s already
  7-argument signature untouched.
- `skills:available` IPC added across `ipc.ts` / `preload` / `main` in lock-step
  per CLAUDE.md.
- Discovery globs `~/.claude/skills` and `<repo>/.claude/skills`; the directory
  name is the invocable id.

## Scope deviation

`src/core/settingsStore.ts` was changed although it is **not** in the plan's
Files Touched. A pre-existing heuristic treated any lone `{id:'claude',
command:'claude'}` agent as the legacy auto-created default and replaced it
with the presets — silently discarding default skills on every load for the
most common configuration. The feature would have looked correct until the next
restart. Minimal fix: the legacy check now also requires no skills to be set.

The wider bug in that heuristic (it also clobbers a renamed or re-iconed lone
Claude entry) is unrelated to this plan and was left alone.

## What is NOT proven

That a real agent honours the injected `/name` line. `CCM_AGENT_CMD` replaces
the agent binary in e2e, so the tests assert the composed command string and
nothing beyond it. The behaviour rests on the live-CLI experiments recorded in
`01-discovery`. A future CLI change to first-line slash handling would break
the feature with every test still green.

## Follow-ups

- Plugin-namespaced skills (`/plugin:skill`) are not enumerable by globbing and
  so never appear in the picker; they work only if typed into the settings
  field.
- Per-agent defaults do not apply to plain (non-New-Task) agent launches —
  there is no initial prompt to prepend to.
- Selecting several large skills is a real context cost: an invoked skill's body
  stays in the conversation for the whole session. No warning is surfaced.
