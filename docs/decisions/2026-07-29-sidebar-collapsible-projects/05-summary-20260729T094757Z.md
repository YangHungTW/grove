# Summary — sidebar collapsible projects

Generated: 2026-07-29T09:47:57Z

Each project group in the Grove sidebar can now be collapsed to just its header
via a caret, the collapsed set survives an app restart, and a Collapse all /
Expand all control sits on the "Projects" section label.

## What made this feature unusual

It was a **re-introduction, not a new build**. `ProjectView.expanded` and
`toggleProjectExpand()` already existed as dead code from an accordion sidebar
that shipped and was removed on the same day back in June. Most of the work was
deciding what to revive and what to leave buried.

Three things the plan's research would not have caught without reading the code:

1. `upsertProject` seeded `expanded: false`. Wiring the field up naively would
   have shipped every project collapsed. The seed now derives from the persisted
   set, which doubles as the entire rehydration path.
2. `setActiveProject` force-expanded, and `init()` calls it at boot — so a
   persisted collapse would have been undone before the user ever saw it. That
   line is gone; the sibling force-expand in `jumpToPending` stays, because an
   attention jump must not land on an invisible worktree.
3. Review caught that `removeProject` never re-derived the persisted set, so
   collapse → close → reopen silently reopened the project collapsed. Fixed and
   regression-tested.

## Design decisions worth remembering

- **Store the collapsed set, not the expanded one.** A newly opened project is
  then expanded by default with zero writes, and `SettingsStore.load()`'s
  existing spread of `DEFAULT_SETTINGS` migrates old settings files for free.
- **Derive, don't mutate.** One `persistCollapsed()` helper recomputes the array
  from live projects, so collapse-all is a single `notify()` + single IPC write
  instead of one per project. The cost is that every mutation site must remember
  to call it — which is exactly the bug review found in `removeProject`.
- **Collapse is presentational only.** Keyboard cycling still traverses
  worktrees inside collapsed projects; auto-expand-on-select was explicitly
  declined. A user can hold an active-but-hidden worktree, reversible in one
  click.

## Known limitations

- A project collapsed in a previous session that is not among the loaded recent
  projects would be dropped from the array by the next persist. Not reachable in
  practice — `init()` loads all recent projects.
- The orphan `.caret` CSS block from the original accordion is still dead. Left
  alone deliberately; removing it is unrelated cleanup.
- No React component tests exist in this repo (`vitest.config.ts` collects only
  `src/**/*.test.ts`, no `@testing-library`), so the caret's rendering is
  covered by the Playwright e2e alone, by design rather than oversight.
