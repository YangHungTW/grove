# Architecture — sidebar collapsible projects

Generated: 2026-07-29T09:36:45Z

Inherits the plan's Implementation Notes. This doc records only what the plan
left open plus the one correction discovery forced.

## Correction to the plan

The plan said "wire up the existing `expanded` field". Discovery found
`upsertProject` seeds it `expanded: false` (`src/renderer/store.ts:636`), so
wiring alone ships everything collapsed. **The seed must derive from the
persisted set:**

```ts
expanded: !(this.settings.collapsedProjects ?? []).includes(repoRoot)
```

`init()` loads settings before any `upsertProject` call, so this is the complete
rehydration — no separate pass. The `?? []` guard keeps a hand-built `Store` in
tests safe if a caller stubs settings without the field.

## Single source of truth for persistence

Collapse state lives on `ProjectView.expanded` (in-memory, authoritative) and is
**derived** into settings on every change by one private helper:

```ts
private persistCollapsed(): void {
  const collapsed = [...this.projects.values()]
    .filter((p) => !p.expanded)
    .map((p) => p.repoRoot)
  void this.updateSettings({ collapsedProjects: collapsed })
}
```

Deriving (rather than add/remove-ing a single key) means:

- Collapse-all / expand-all are one `updateSettings` → **one `notify()`, one
  `settingsSave`**, satisfying the plan's "not one per project" requirement.
- Closed projects drop out of the persisted array automatically — no stale keys.

Trade-off accepted: a project collapsed in a previous session but *not currently
open* would be dropped from the array by the next persist. All recent projects
are loaded during `init()`, so this does not arise in practice.

## Public API added to `Store`

| Method | Behaviour |
| --- | --- |
| `toggleProjectExpand(repoRoot)` | existing (dead) method; now flips `expanded` then `persistCollapsed()` |
| `collapseAllProjects()` | sets `expanded = false` on all, one persist |
| `expandAllProjects()` | sets `expanded = true` on all, one persist |
| `anyProjectExpanded()` | selector driving the Collapse-all/Expand-all button label |

`updateSettings` already calls `notify()` synchronously before awaiting the IPC
save, so `toggleProjectExpand` no longer needs its own `notify()`.

## The two force-expand sites

- `setActiveProject` (`store.ts:673`) — **deleted**. `init()` calls it on the
  first project at boot, so leaving it would undo a persisted collapse before
  the user ever saw it.
- `jumpToPending` (`store.ts:1377`) — **kept**, and now followed by
  `persistCollapsed()` so the expansion it forces is durable. Rationale: this is
  an explicit attention jump; landing the user on an invisible worktree is a bug,
  not a feature.

## UI

`ProjectGroup` gains a leading caret button inside `.project-header`:

```tsx
<button className="project-caret" aria-expanded={project.expanded}
        title={project.expanded ? 'Collapse project' : 'Expand project'}
        onClick={() => store.toggleProjectExpand(project.repoRoot)}>
  <ChevronDownIcon size={12} />
</button>
```

- Class name `project-caret` is contractual — `e2e/smoke.mjs` selects on it.
- Collapsed state rotates the chevron −90° via CSS, reusing the existing
  `ChevronDownIcon` rather than adding a chevron-right (plan directive).
- `{project.expanded && <div className="worktrees">…</div>}` — the sibling is
  removed from the DOM, not hidden, so the e2e `.card` count goes to exactly 0.
- The `.section-label` div becomes a flex row carrying one text button that
  reads "Collapse all" when any project is expanded, else "Expand all".

### Attention indicator (the open question from discovery)

The sidebar has no session-level nesting, so the aggregate is computed per
project over its worktrees using the existing selector:

```ts
const attention = [...project.worktrees.values()]
  .filter((wt) => s.worktreePending(wt.id)).length
```

Rendered as `.project-attention` **only when collapsed and non-zero**, so an
expanded project's header is visually unchanged from today (the per-card
`.attention` styling already covers that case). `.project-count` stays in the
header unconditionally, so it survives collapse for free.

## Test strategy

- **`store.test.ts`** — new `describe` block. `seedProject` is reused for the
  toggle/collapse-all/setActiveProject tests. Criterion 1(d) needs the real
  `init()`, which touches `document.fonts` (absent in jsdom) and 5 `on*` IPC
  registrations; handled by a local `installInitApi()` that `defineProperty`s a
  stub `document.fonts` and wraps the api object in a `Proxy` whose `get` falls
  back to a no-op `vi.fn()`. This keeps the stub honest about the handful of
  calls that matter (`settingsLoad`, `projectListRecent`, `worktreeList`,
  `repoRoot`, `projectAdd`) without hand-listing every listener.
- **`settingsStore.test.ts`** — default + round-trip assertions, importing
  `DEFAULT_SETTINGS` from `./settingsStore` to match the file's existing style.
- **`e2e/smoke.mjs`** — caret click/re-click around the existing assertions.
